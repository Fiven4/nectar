ВВЕДЕНИЕ
Наименование программы
Наименование - «Интернет-магазин продуктов «Нектар».
Краткая характеристика области применения программы
Приложение предназначено к применению в сфере электронной коммерции для автоматизации процесса розничной торговли продуктами питания с доставкой. Система обеспечивает взаимодействие между магазином, покупателем и курьером через мобильное устройство, а также предоставляет сотрудникам магазина инструменты управления каталогом, заказами и пользователями через веб-панель.
ОСНОВАНИЕ ДЛЯ РАЗРАБОТКИ
Основание для проведения разработки
Основанием для проведения разработки является задание по курсовому проекту по МДК 01.01 «Разработка программных модулей».
Наименование и условное обозначение для разработки
Наименование темы разработки - «Разработка мобильного приложения и веб-панели управления для интернет-магазина продуктов "Нектар"»
НАЗНАЧЕНИЕ РАЗРАБОТКИ
Функциональное назначение программы
Функциональным назначением программы является учет товарных позиций и их остатков, автоматизация оформления и выполнения заказов и информационное сопровождение клиентов.
Эксплуатационное назначение программы
Программа должна эксплуатироваться в подразделениях:
Веб-версия (веб-панель): в отделе продаж и логистики магазина «Нектар». Сотрудники используют её для управления каталогом товаров и остатками, обработки входящих заказов, назначения курьеров, управления промокодами и пользователями.
Мобильная версия: предназначена для использования широким кругом лиц – покупателями для ознакомления с ассортиментом и совершения покупок, а также курьерами магазина для выполнения доставок.
Конечным пользователем программы будут клиенты магазина и персонал магазина – администраторы, менеджеры и курьеры.
ТРЕБОВАНИЯ К ПРОГРАММЕ
Требования к функциональным характеристикам
Требования к составу выполняемых функций
Программа должна обеспечивать выполнение следующих функций: регистрация новой учетной записи покупателя с вводом логина, имени, телефона, email и пароля, авторизация пользователя по логину или email и паролю, вход через аккаунт Google, восстановление утерянного пароля через электронную почту, просмотр главного экрана с акционным баннером, популярными товарами и товарами по категориям, просмотр каталога по категориям, поиск товаров по названию, фильтрация товаров по производителям и диапазону цен, сортировка списка товаров, просмотр карточки товара с описанием, характеристиками и пищевой ценностью, добавление и удаление товаров в списке «Избранное», добавление товаров в корзину с контролем остатков, изменение количества товаров в корзине, удаление товаров из корзины, ввод и проверка промокода на скидку, автоматический расчет стоимости заказа с учетом скидки и доставки, оформление заказа с выбором сохраненного адреса, интервала доставки и способа оплаты (онлайн-картой или наличными), сохранение заказа в базе данных с одновременным списанием остатков, отображение истории заказов и хода их выполнения, подтверждение получения заказа, получение уведомлений об изменении статуса заказа, редактирование профиля и аватара, управление адресами доставки и банковскими картами (хранятся только маски), смена пароля, переключение языка интерфейса (русский и английский), удаление аккаунта, выход из учетной записи.
В части курьера программа должна обеспечивать: просмотр пула свободных заказов, взятие заказа в работу (два курьера не могут взять один заказ), возврат заказа в пул до начала доставки, просмотр активных заказов и истории доставок, копирование телефона клиента, начало доставки и подтверждение доставки, получение уведомлений о назначенных заказах.
В административной части программы (веб-панель) должны выполняться функции: авторизация администратора и менеджера, просмотр дашборда (покупатели, активные заказы, товары с низким остатком, выручка, продажи по месяцам, ТОП-5 товаров), управление каталогом товаров (создание, изменение, скрытие и восстановление карточек, управление остатками), управление категориями, производителями, поставщиками и промокодами, просмотр списка заказов, смена статуса заказа и назначение курьера (с уведомлением покупателя и курьера и возвратом товаров на склад при отмене), управление пользователями (просмотр, смена роли, отключение и восстановление – только для администратора), смена пароля, переключение языка интерфейса.
Требования к переменным
Наименования переменных, полей и функций в клиентской части (Dart) должны соответствовать стилю lowerCamelCase, классов – UpperCamelCase, файлов – snake_case. Наименования переменных веб-панели (JavaScript) должны соответствовать стилю camelCase. Переменные должны иметь осмысленные названия, отражающие их содержимое.
Требования к функциям приложения (стиль оформления функций в коде)
Функции должны быть именованы глагольными словосочетаниями, отражающими выполняемое действие.
Для Dart: стиль lowerCamelCase. Соблюдение рекомендаций Effective Dart и правил пакета flutter_lints.
Для JavaScript: стиль camelCase, использование ES-модулей.

Требования к ролям пользователей
Неавторизованный пользователь
Это пользователь, который установил мобильное приложение, но не прошел авторизацию.
Права и возможности:
Просмотр экрана загрузки и приветствия, переключение языка интерфейса.
Доступ к экранам авторизации, регистрации и восстановления пароля.
Покупатель
Это основной пользователь мобильного приложения, прошедший авторизацию. Обладает всеми правами неавторизованного пользователя, а также расширенным функционалом.
Права и возможности:
Просмотр каталога, поиск, фильтрация и сортировка товаров, просмотр карточки товара.
Добавление и удаление товаров в разделе «Избранное».
Добавление товаров в корзину, изменение количества, применение промокодов, выбор адреса, времени доставки и способа оплаты, оформление заказа.
Просмотр истории своих заказов и уведомлений, подтверждение получения заказа.
Редактирование профиля, аватара, адресов и карт, смена пароля, смена языка, удаление аккаунта, выход из аккаунта.
Курьер
Это пользователь мобильного приложения, отвечающий за доставку заказов.
Права и возможности:
Просмотр пула свободных заказов, взятие заказа в работу и возврат его в пул до начала доставки.
Просмотр своих активных заказов и истории, перевод заказа в статусы «В пути» и «Доставлен».
Смена языка, выход из аккаунта.
Менеджер
Это пользователь, имеющий доступ к веб-панели. Роль предназначена для ведения каталога и обработки заказов.
Права и возможности:
Создание и изменение карточек товаров, управление остатками, скрытие и восстановление товаров.
Управление категориями, производителями и промокодами; просмотр поставщиков.
Просмотр заказов, смена статуса заказа, назначение курьера.
Просмотр списка пользователей, смена пароля, выход из аккаунта.
Администратор
Это пользователь, имеющий полный доступ к веб-панели. Роль предназначена для управления контентом, пользователями и бизнес-процессами магазина.
Права и возможности:
Все возможности менеджера.
Полное удаление товаров и управление поставщиками.
Смена роли пользователей, отключение и восстановление учетных записей.
Перезаливка стартового каталога товаров.
Требования к регистрации новой учетной записи
Для регистрации пользователю необходимо на экране входа нажать «Зарегистрироваться» и заполнить следующие поля, к которым предъявляются правила валидации:
Поле «Логин»: текстовое поле. Разрешены латинские буквы, цифры и символы «.», «_», «-». Длина от 3 до 50 символов. Логин должен быть уникальным.
Поле «Имя»: текстовое поле. Разрешены буквы русского и латинского алфавитов, пробел и дефис. Ввод цифр и специальных символов запрещен. Длина от 2 до 50 символов.
Поле «Телефон»: текстовое поле. Разрешены цифры, знак «+», пробелы, скобки и дефис; количество цифр от 10 до 15.
Поле «Email»: текстовое поле. Строка должна содержать один символ «@» и корректное доменное имя, состоять из латинских букв, цифр и допустимых символов («.», «_», «%», «+», «-»), длиной не более 100 символов. Пробелы и кириллица не допускаются. Email должен быть уникальным.
Поле «Пароль»: текстовое поле со скрытым вводом. Минимальная длина – 6, максимальная – 128 символов, пробелы запрещены, обязательна хотя бы одна цифра.
Поле «Подтверждение пароля»: значение должно совпадать с полем «Пароль».
После корректного заполнения полей пользователю необходимо нажать кнопку «Зарегистрироваться». В случае успешной проверки программа должна создать учетную запись, сохранить профиль с ролью «Покупатель» в базе данных и автоматически выполнить вход.
Требования к авторизации
Для входа в мобильное приложение пользователю необходимо заполнить поля «Логин или email» и «Пароль» и нажать кнопку «Войти». В случае успеха открывается главный экран приложения согласно роли пользователя (покупатель – «Магазин», курьер – «Доставка»).
Для входа в веб-панель сотрудник открывает веб-страницу в браузере, вводит email и пароль (со скрытым вводом, не более 128 символов) и нажимает кнопку «Войти» мышью или клавишей Enter. Вход разрешен только ролям «Администратор» и «Менеджер».
Требования к восстановлению утерянного пароля
Для восстановления пароля пользователю необходимо на экране авторизации нажать на ссылку «Забыли пароль?», ввести свой email (латинские буквы, цифры и допустимые символы, обязательное наличие «@» и доменной зоны) в текстовое поле и нажать кнопку «Отправить письмо». На почту должна прийти ссылка для создания нового пароля.
Требования к поиску товаров
Для поиска товара пользователю необходимо нажать на строку поиска на экране «Магазин» или «Каталог» и ввести с клавиатуры часть названия (минимум 1 символ). Список товаров обновляется автоматически по мере ввода.
Требования к фильтрации товаров
Для настройки фильтров пользователю необходимо ввести запрос в строку поиска каталога и нажать кнопку с иконкой фильтра (либо иконку фильтра на экране категории). В открывшемся окне пользователь передвигает ползунок диапазона цены и выбирает производителей нажатием на соответствующие кнопки. Для подтверждения действий нажимается кнопка «Применить», для отмены – «Сбросить».
Требования к сортировке списка товаров
Для сортировки пользователю необходимо в окне фильтров выбрать один из вариантов: «По умолчанию», «Сначала свежие», «По убыванию цены» или «По возрастанию цены» и нажать «Применить».
Требования к добавлению и удалению товаров в списке «Избранное»
Для добавления товара в избранное пользователю необходимо нажать на иконку «сердце» в карточке товара. Иконка должна изменить цвет. Для удаления товара необходимо повторно нажать на закрашенную иконку «сердце». Просмотр списка выполняется по иконке «сердце» на экране «Магазин».
Требования к добавлению товаров в корзину
Для добавления в корзину пользователю необходимо в карточке товара выбрать количество кнопками «+» и «−» и нажать кнопку «В корзину» либо нажать кнопку «+» на карточке товара в списке. Количество одной позиции не может превышать остаток товара и 99 единиц.
Требования к изменению количества и удалению товаров из корзины
Для изменения количества пользователю необходимо на экране корзины нажать на кнопку «+» или «−» рядом с товаром. Для удаления товара необходимо нажать на кнопку «×» или уменьшить количество до нуля.
Требования к вводу промокода на скидку
Для применения скидки пользователю необходимо в окне оформления заказа нажать «Выбрать» в строке «Промокод», ввести с клавиатуры код (латинские буквы и цифры) либо выбрать его из списка и нажать кнопку «Применить». В случае успеха выводится сообщение о размере скидки (от 1 до 99 %), итоговая сумма пересчитывается. Просроченный или неактивный промокод не принимается.
Требования к расчету стоимости заказа
Стоимость рассчитывается автоматически: подытог – сумма цен товаров, скидка – процент от подытога, доставка – 149 ₽ (бесплатно, если сумма после скидки не меньше 1500 ₽), итог – подытог за вычетом скидки плюс доставка. Пользователь считывает значения в блоке расчета на экранах «Корзина» и «Оформление заказа».
Требования к оформлению заказа
Для перехода к оформлению пользователю необходимо нажать кнопку «Оформить заказ» в корзине. В открывшемся окне пользователь выбирает сохраненный ранее адрес доставки (адрес добавляется в разделе «Профиль» → «Адрес доставки», длина от 1 до 300 символов), интервал доставки («Как можно скорее (до 60 минут)» или двухчасовой интервал с 09:00 до 21:00) и способ оплаты: «Онлайн» – с выбором сохраненной карты (номер карты состоит из 16 цифр, в базе хранится только маска) или «Наличными» курьеру. Затем нажимается кнопка «Разместить заказ». Программа проверяет остатки, списывает товары со склада, создает заказ со статусом «Новый», очищает корзину и выводит номер заказа.
Требования к просмотру истории заказов
Для просмотра истории пользователю необходимо перейти в раздел «Профиль» и выбрать пункт «Заказы». Для каждого заказа отображаются номер, дата и ход выполнения. При нажатии на заказ карточка раскрывается и показывает адрес, время доставки, способ оплаты, курьера, итоговую сумму и состав заказа. Завершенные и отмененные заказы можно скрыть из списка.
Требования к подтверждению получения заказа
Пока заказ находится у курьера или доставлен, в раскрытой карточке заказа отображается кнопка «Подтвердить, что всё хорошо». После нажатия отображается сообщение о подтверждении получения.
Требования к просмотру уведомлений
Для просмотра уведомлений пользователю необходимо перейти в «Профиль» → «Уведомления». Здесь отображаются сообщения об изменении статуса заказа и назначении курьера, а также переключатели Push-, SMS- и Email-уведомлений. Кнопка «Очистить все» удаляет историю уведомлений.
Требования к редактированию профиля
Для изменения данных пользователю необходимо в разделе «Профиль» выбрать «Мои данные». Пользователь изменяет поля «Полное имя» (только буквы, пробелы и дефисы, от 2 до 50 символов) и «Номер телефона» (от 10 до 15 цифр) и нажимает кнопку «Сохранить». Email изменить нельзя. Для смены аватара пользователь нажимает на текущее фото и выбирает изображение из галереи устройства (разрешены форматы JPEG и PNG, после сжатия размер не более 150 КБ).
Требования к смене пароля
Для смены пароля пользователю необходимо выбрать пункт «Сменить пароль», ввести текущий пароль, новый пароль (не менее 6 символов, без пробелов, минимум одна цифра, не совпадает с текущим) и его подтверждение, после чего нажать кнопку «Сохранить».
Требования к настройке языка
Для смены языка пользователь нажимает на переключатель «RU/EN» в профиле (или на экранах приветствия и входа). Весь интерфейс приложения переключается на выбранный язык, выбор сохраняется на устройстве.
Требования к выходу из учетной записи и удалению аккаунта
Для выхода пользователю необходимо в разделе «Профиль» нажать кнопку «Выйти». Для удаления аккаунта необходимо нажать «Удалить аккаунт» и подтвердить действие; удаление невозможно при наличии незавершенных заказов.
Требования к работе курьера с заказами
Курьер на вкладке «Свободные» нажимает «Взять заказ», после чего заказ получает статус «Передан курьеру». До начала доставки заказ можно вернуть в пул кнопкой «Вернуть в пул» с подтверждением. Кнопка «Начать доставку» переводит заказ в статус «В пути». Кнопка «Подтвердить доставку» после подтверждения переводит заказ в статус «Доставлен»; отмена действия невозможна.
Требования к просмотру и изменению статуса заказа в веб-панели
Для работы с заказами сотруднику необходимо перейти в раздел «Заказы». Для изменения статуса в строке заказа выбираются новый статус (из списка: «Новый», «В сборке», «Передан курьеру», «В пути», «Доставлен», «Отменен») и курьер, после чего нажимается кнопка «Сохранить». Для статусов «Передан курьеру», «В пути» и «Доставлен» курьер обязателен. При отмене заказа (после подтверждения) товары возвращаются на склад. Завершенные и отмененные заказы изменять нельзя.
Требования к управлению каталогом товаров и остатками
Для добавления товара сотруднику необходимо нажать кнопку «Добавить товар» и заполнить поля: название (от 1 до 255 символов), цена (значение больше 0, не более 1 000 000, допускаются сотые доли), количество на складе (целое от 0 до 9999), единица (до 50 символов), категория и производитель (обязательный выбор из справочника), поставщик (необязательно), ссылка на изображение (http:// или https://), страна, срок годности, пищевая ценность (от 0 до 10 000), состав и описание (до 2000 символов) на русском и английском языках. В конце необходимо нажать «Сохранить». Для скрытия товара сотрудник нажимает кнопку «Удалить» и подтверждает действие; скрытый товар можно восстановить.
Требования к управлению справочниками и промокодами
Категории (название до 100 символов, описание до 500), производители (название, страна, телефон) и поставщики (название, ИНН из 10 или 12 цифр, адрес до 300 символов, телефон, email) создаются и изменяются в соответствующих разделах кнопками «Добавить» и «Редактировать». Названия должны быть уникальны; запись, к которой привязаны товары, удалить нельзя. Промокод состоит из латинских букв и цифр (до 30 символов), имеет скидку от 1 до 99 % и срок действия не раньше текущей даты; промокод, используемый в незавершенных заказах, удалить нельзя.
Требования к управлению пользователями
Администратор в разделе «Пользователи» выбирает роль в списке и нажимает «Сохранить роль» либо нажимает «Отключить» и подтверждает действие. Нельзя изменить свою роль, отключить себя и последнего администратора, а также изменить роль или отключить пользователя с незавершенными заказами. Отключенных пользователей можно показать флажком «Показывать отключенных» и восстановить кнопкой «Восстановить».
Требование к письмам на почту
Программа должна обеспечивать отправку на электронную почту пользователя письма со ссылкой для создания нового пароля сразу после нажатия кнопки «Отправить письмо» на экране восстановления пароля. Письмо формируется сервисом Firebase Authentication на языке интерфейса приложения.
Требования к подключению базы данных
База данных: программа должна использовать облачную документоориентированную базу данных Google Cloud Firestore. База данных отвечает за постоянное хранение информации о пользователях, каталоге товаров, справочниках, промокодах, заказах и уведомлениях. Отдельный серверный код и REST API не разрабатываются: мобильное приложение и веб-панель обращаются к базе данных напрямую через Firebase SDK, а права доступа контролируются правилами безопасности Firestore (файл firestore.rules).
Аутентификация: регистрация и вход выполняются средствами Firebase Authentication (email и пароль, Google Sign-In).
Требования к дизайну приложения
Дизайн мобильного приложения должен быть выполнен в светлой цветовой теме с зелеными акцентами.
Основной фон: светло-бежевый (#F5F3EF), поверхности карточек – белые.
Основной цвет: зеленый (#2E7D32), темный оттенок – #1B5E20. Цвет применяется для кнопок целевых действий («В корзину», «Разместить заказ», «Войти»), активных иконок и акцентов. Кнопки опасных действий выделяются красным (#C62828).
Шрифты: заголовки – Unbounded, основной текст – шрифт без засечек (Sans-serif) для обеспечения высокой читаемости. Все сочетания цвета текста и фона должны соответствовать контрасту не ниже 4.5:1 (WCAG AA).
Требования к таблицам базы данных
Специальные требования к архитектуре БД не предъявляются, однако все коллекции и поля документов должны быть названы на английском языке в стиле camelCase. Примеры названий коллекций: users, products, categories, manufacturers, suppliers, promoCodes, orders, orderStatuses, notifications, loginIndex.
Требования к организации входных данных
Входные данные поступают в систему от пользователя через экранные формы (ввод текста с клавиатуры, переключатели, выбор из списков и файлов).
1. Окна «Вход», «Регистрация» и «Восстановление пароля»:
Логин: тип String. Требования: 3–50 символов, латиница, цифры и символы «.», «_», «-».
Имя: тип String. Требования: обязательное поле, только буквы, пробелы и дефисы, длина от 2 до 50 символов.
Email: тип String. Требования: обязательное поле, наличие символа «@» и домена (формат *@*.*), не более 100 символов.
Пароль: тип String. Требования: обязательное поле, скрытый ввод, от 6 до 128 символов, без пробелов, минимум одна цифра.
2. Окна «Магазин», «Каталог» и «Фильтры»:
Строка поиска: тип String. Требования: запуск поиска при длине от 1 символа.
Сортировка: тип Enum (по умолчанию, сначала свежие, по убыванию цены, по возрастанию цены).
Выбор производителей: тип Set of Strings (множество выбранных значений).
Диапазон цены (от и до): тип Double. Требования: значение «до» ≥ «от», ≥ 0.
3. Окна «Корзина» и «Оформление заказа»:
Количество товара (+ / −): тип Integer. Требования: от 1 до min(остаток, 99).
Промокод: тип String. Требования: латинские буквы и цифры, без спецсимволов.
Адрес доставки: тип String. Требования: выбор из сохраненных адресов.
Способ оплаты: тип String (Онлайн или Наличными); карта: выбор из сохраненных.
4. Окна «Профиль» и настройки:
Номер телефона: тип String. Требования: цифры и знаки «+», «-», «(», «)», пробел; 10–15 цифр.
Аватар пользователя: тип File (форматы JPEG, PNG; после сжатия до 150 КБ).
Смена пароля: поля «Текущий пароль», «Новый пароль», «Повтор нового пароля» (тип String, скрытый ввод).
Уведомления Push/SMS/Email: тип Boolean (переключатель On/Off).
Язык интерфейса: тип String (выбор из списка: RU, EN).
5. Окна курьера и административной веб-панели:
Действие курьера: кнопки «Взять заказ», «Вернуть в пул», «Начать доставку», «Подтвердить доставку».
Управление товаром: название, описание (тип String), цена (Double, > 0), количество (Integer, 0–9999), ссылка на изображение (String).
Управление справочниками и промокодами: строковые и числовые поля согласно разделу 4.1.
Управление заказами: изменение статуса заказа – тип Enum (выбор из выпадающего списка), курьер – выбор из списка.
Управление пользователями: роль – тип Enum (администратор, менеджер, курьер, покупатель).
Требования к организации выходных данных
Выходные данные формируются базой данных и визуализируются в интерфейсе приложения или веб-панели.
1. Экраны «Магазин» и «Каталог»:
Акционный баннер: строка (String) с описанием скидки и промокодом.
Карточки товаров: главное фото (Image), название (String), фасовка (String), цена (Double с символом валюты), остаток.
Детали товара: описание (String), характеристики, пищевая ценность (Double), остаток (Integer).
2. Экраны «Избранное» и «Корзина»:
Список избранного: карточки товаров, сохраненных пользователем (фото, название, цена).
Содержимое корзины: миниатюра товара (Image), название (String), фасовка, количество (Integer).
Финансовые расчеты: подытог, скидка, доставка, итог (тип Double).
3. Экраны «Заказы», «Профиль» и «Доставка»:
Профиль: имя, email, роль (String), аватар (Image).
Список заказов: номер (String), дата (DateTime), ход выполнения, итоговая сумма (Double).
Детализация заказа: адрес, время и способ оплаты, курьер и его телефон, перечень товаров с количеством.
Заказы курьера: адрес, время, клиент и телефон, состав, сумма и сумма к получению наличными.
4. Системные уведомления (Оба приложения):
Сообщения об ошибках / успехах (SnackBar / Toast): текстовые сообщения (String), например: «Неверный email или пароль.», «Промокод SALE10 применен. Скидка 10%.», «Заказ взят в работу».
5. Окна административной веб-панели:
Дашборд: показатели (Integer, Double) и столбчатые диаграммы.
Таблицы товаров, справочников, заказов и пользователей: форматированный вывод данных.
Требования к надежности
Требования к обеспечению надежного (устойчивого) функционирования программы
Надежное (устойчивое) функционирование программы должно быть обеспечено организацией бесперебойного питания технических средств и устойчивого подключения к сети Интернет. Целостность данных при оформлении заказа обеспечивается выполнением проверки остатков, списания и создания заказа в одной транзакции базы данных.
Время восстановления после отказа
Время восстановления после отказа, вызванного сбоем электропитания технических средств не должно превышать времени, необходимого на перезагрузку операционной системы и запуск программы, при условии соблюдения условий эксплуатации технических и программных средств.
Время восстановления после отказа, вызванного неисправностью технических средств, не должно превышать времени, требуемого на устранение неисправностей технических средств и переустановки программных средств.
Отказы из-за некорректных действий оператора
Отказы программы возможны вследствие некорректных действий пользователя при взаимодействии с операционной и информационной системой.
Во избежание возникновения отказов программы по указанной выше причине следует провести инструктаж с конечным пользователем о правильной эксплуатации информационной системы и убедиться в том, что конечный пользователь имеет опыт использования ЭВМ.
Условия эксплуатации
Климатические условия эксплуатации
Климатические условия эксплуатации, при которых должны обеспечиваться заданные характеристики, должны удовлетворять требованиям, предъявляемым к техническим средствам в части условий их эксплуатации.
Требования к видам обслуживания
Требования к видам обслуживания не предъявляются.
Требования к численности и квалификации персонала
Сотрудники должны иметь базовое умение работы с персональным компьютером и веб-браузером.
Требования к составу и параметрам технических средств
Клиентская часть (Мобильное устройство):
В состав технических средств должен входить смартфон или планшетный компьютер, включающий в себя:
а) процессор с архитектурой ARM, тактовой частотой 1.5 ГГц и выше;
б) оперативную память объемом не менее 2 ГБ;
в) свободное место во встроенной памяти устройства объемом не менее 100 МБ;
г) сенсорный экран (дисплей) с поддержкой технологии Multi-touch;
д) модуль беспроводной связи (Wi-Fi или 3G/4G/LTE) для обеспечения постоянного доступа к сети Интернет.
Административная часть (Рабочее место сотрудника / разработчика):
В состав технических средств должен входить IBM-совместимый персональный компьютер (ПЭВМ) или ноутбук, включающий в себя:
а) процессор с тактовой частотой не менее 2.0 ГГц;
б) оперативную память объемом не менее 8 ГБ (необходимо для комфортного запуска сред разработки, эмулятора смартфона и эмуляторов Firebase);

Требование к исходному коду и языкам программирования
Клиентская часть (Мобильное приложение): Исходные коды мобильного приложения должны быть реализованы на языке программирования Dart с использованием кроссплатформенного фреймворка Flutter (версии 3 и выше, Dart 3.9 и выше). В качестве интегрированной среды разработки (IDE) программы должна быть использована среда Visual Studio Code или Android Studio.
Административная часть: Исходные коды веб-панели управления должны быть реализованы на языке JavaScript (ES-модули) с использованием Firebase Web SDK, без сборщика проекта. Правила безопасности базы данных должны быть описаны на языке правил Cloud Firestore. В качестве среды разработки должна быть использована среда Visual Studio Code.
Требования к программным средствам, используемым программой
Для обеспечения бесперебойного функционирования программы требуются следующие программные средства:
а) На клиентском мобильном устройстве: операционная система Android (версии 8.0 и выше) или операционная система iOS (версии 15.0 и выше).
б) На рабочем месте сотрудника: операционная система семейства Windows 10/11, macOS или Linux; современный веб-браузер (Google Chrome, Safari, Mozilla Firefox или Yandex Browser актуальных версий) для доступа к веб-панели.
в) Облачные сервисы: проект Google Firebase с включенными Authentication (провайдеры «Электронная почта/пароль» и Google), Cloud Firestore и Hosting.
г) Для разработки и тестирования: Flutter SDK, Node.js версии 20 и выше, Firebase CLI, Java (для запуска локальных эмуляторов Firebase).
Требования к защите информации и программ
Права доступа к данным должны определяться ролями пользователей (администратор, менеджер, курьер, покупатель) и контролироваться правилами безопасности Cloud Firestore: покупатель видит только свой профиль и заказы, курьер – только свои активные заказы и пул свободных, изменение ролей и отключение учетных записей доступно только администратору, заказы физически не удаляются. Пароли хранятся и проверяются сервисом Firebase Authentication, номера банковских карт в базе данных не хранятся (сохраняется только маска). Веб-панель должна экранировать выводимые данные (защита от XSS).
